## 1. Слова владельца (дословно, `GOAL.md` строки 3–20 и 487–493)

> - Что?
> Андроид приложение для апскейлинга изображений на движке от известного приложения Upscayl.
>
> - Название?
> KARTUN
> Krinik Android Restoration Tool for Upscaling with Neural Networks
> Open-source · Offline · AI-powered
>
> - Чем вдохновляемся?
> Простатой оригинального десктопного Upscayl для Виндовз. Есть локально на этой машине для реверс инжиниринга UI/UX. И проектом KrinikCam - для использования узнаваемого Криником стиля приложения, в его любимом темно розовом стиле.
>
> - Языки?
> Мультиязычное, 10 главных языков мира.
>
> - Платформы?
> Современные Андроид устройства от Андроид 16 и выше. Снепдрегоны, Медиатеки мощные с GPU ускорителями. Буду давать на провод девайсы по вечерам.

> - Личный заказ от владельца Николая:
> - Опенсоурс
> - МИТ лицензия по возможности, можно и другую, которая нам дают больше прав на монетизацию
> - больше выходных и входных форматов изображения. Входных прям очень много нужно, выходные - штуки 4...5 самым популярных, обязательно webP, Png, Jpeg с настройкой качества при сохранении.
> - Возможность пошейрить результат через стандартный андроид шейринг.
> - Возможность скачать изображение по ссылке вставив на нее ссылку прямо из буфера обмена в приложение.
> - Просмотр "До-После" с полнузком, который можно пальцем схватить, как в оригинальном десктопном приложении.

## 2. Консультация ЧатГПТ в `GOAL.md` — сжато (строки 24–484)

| § оригинала | Суть |
|---|---|
| §1 Цель | полностью офлайн, обработка на устройстве; Real-ESRGAN + NCNN, ускорение Vulkan где доступно; без регистрации, рекламы, подписок, телеметрии; APK; открытый код. Главный принцип: выбрал фото → одна кнопка → результат |
| §2 Стек | Kotlin, Jetpack Compose, MVVM, корутины; NCNN + Vulkan; Photo Picker; MediaStore/SAF; Gradle + NDK; JUnit и инструментальные тесты. Изучить код и лицензию движка до интеграции; JNI-обёртка Kotlin↔C++; ядро не переписывать на Kotlin. Vulkan на устройстве не гарантирует работу — нужна проверка и запасной путь |
| §3 Интерфейс | один основной экран, минимум настроек (эскиз — концепция, не требование к раскладке). Сценарий: открыть → выбрать фото → превью и разрешение → модель и масштаб → «Улучшить» → прогресс → результат → сравнение → сохранить/поделиться. UX: системный выбор фото без доступа ко всей галерее; без технических параметров модели; понятные ошибки; настройки сохраняются; исходник не теряется; интерфейс не блокируется |
| §4 Модели | P0 Real-ESRGAN x4plus, P1 x4plus-anime, P2 другие; модели отдельно от кода, если возможно; для MVP базовая модель встроена; у каждой проверить лицензию, формат, совместимость с версией NCNN |
| §5 Движок | C++ с JNI: инициализация NCNN, загрузка модели, апскейл, ошибки, освобождение GPU/CPU, отмена. Приоритет: Vulkan → CPU → понятное сообщение; CPU не равен GPU по скорости. Большие изображения: оценка размера до запуска, контроль памяти, тайлы с проверкой стыков, обработка нехватки памяти; 4000×3000 ×4 = 192 Мп. Тайлы — часть плана, а не поздняя оптимизация |
| §6 Результат | отдельный экран: оригинал, результат, зум пальцами, перемещение, переключение; желательно — ползунок «до/после». Разрешения исходника и результата, время обработки |
| §7 Сохранение | PNG и JPEG (качество для JPEG); в галерею, понятное имя, оригинал не перезаписывается, уведомление об успехе, EXIF корректно |
| §8 Совместимость | (консультация: Android 12+, владелец задал Android 16+) ARM64, Snapdragon и Dimensity, Vulkan и CPU-путь. Не зависать, переживать отмену и сворачивание, не падать при нехватке памяти, не терять исходник, не отправлять изображения на сервер. «О приложении»: устройство, Android, Vulkan, режим, версия движка, модель |
| §9 Структура | `app/` (ui, viewmodel, domain, data, nativebridge, cpp, assets/models), `native/ncnn`, `docs/` (архитектура, лицензии моделей), README, LICENSE — логическая схема |
| §10 Этапы | 1 исследование и прототип на Android (P0) → 2 рабочий движок (P0) → 3 базовый интерфейс (P0) → 4 сохранение и обмен (P0) → 5 большие изображения (P1) → 6 полировка (P1) |
| §11 Приёмка MVP | 1 сборка APK без ручной правки; 2 установка на ARM64; 3 выбор через системный интерфейс; 4 реальная нейросеть; 5 видимое увеличение разрешения; 6 работа без сети; 7 сохранение в галерею; 8 без падения при ошибке модели; 9 разные размеры; 10 инструкция по сборке; 11 лицензии приложения, движка, моделей; 12 известные ограничения в README. Не нужны: аккаунты, облако, подписки, редактор, сложная история |
| §12 Запреты агенту | не имитировать апскейл фильтрами; не менять Real-ESRGAN без согласования; не подменять локальную обработку удалённым API; без аналитики, телеметрии, рекламы; не скачивать исполняемый код во время работы; компиляция ≠ доказательство работы; Vulkan не заявлять без проверки; не игнорировать ошибки модели; без заглушек в основном сценарии; не копировать Upscayl без проверки лицензии; ничего вне MVP до рабочего прототипа |
