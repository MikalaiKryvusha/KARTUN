## 1. Цель

**Боль.** Upscayl хорошо увеличивает фото на компьютере, на телефоне такого простого офлайн-инструмента у владельца нет.
Аналоги на Android либо застряли на старом Android (тянут движок отдельной программой и не попадают в Google Play), либо
держат код под GPL/AGPL, либо считают на процессоре (`researches/03` §B).

**Цель (Achieve).** На Android 16 пользователь выбирает фото, нажимает одну кнопку, видит прогресс и получает изображение,
увеличенное нейросетью в 2 или 4 раза, за время, замеренное на Титане (критерий 2.6). Он сравнивает результат с оригиналом ползунком, сохраняет в галерею
или отправляет через «Поделиться». Изображение не покидает устройство при обработке.

## 2. Критерии приёмки MVP

Источник каждого критерия — `GOAL.md` §11 или личный заказ владельца; числа, выбранные агентом, помечены `[AI]`. Проверку проводит агент на планшете Titan 1
(`HOUSE_RULES.md` §3) и записывает отчётом прогона в `testcases/reports/`.

2.1 **Сборка.** Проект собирается в APK одной командой из `AGENT_GUIDE.md` → Build, без ручной правки исходников.
Проверка: команда завершается с кодом 0, APK появляется в `app/build/outputs/apk/`.

2.2 **Установка.** APK ставится на Титан (Android 16, arm64-v8a) и запускается. Проверка: `adb install -r` печатает
`Success`, главный экран виден на снимке экрана.

2.3 **Выбор фото.** Фото выбирается системным выбором фотографий Android, без запроса доступа ко всей галерее.
Проверка: в манифесте нет разрешений `READ_MEDIA_IMAGES` и `READ_EXTERNAL_STORAGE`.

2.4 **Настоящая нейросеть.** Апскейл выполняет модель Real-ESRGAN. Проверка: результат тестового изображения 256×256
моделью 4× имеет размер 1024×1024 и совпадает с эталоном движка на ПК в пределах допуска сверки, а от бикубического
увеличения этого тестового изображения отличается сильнее этого допуска (допуск по замеру фазы 0 — PSNR не ниже 38 дБ к эталону; у бикубика 31,1 дБ).

2.5 **Офлайн-обработка.** Обработка работает в режиме полёта. Проверка: прогон на Титане с выключенной сетью даёт результат.

2.6 **Скорость.** Время обработки фото 1 Мп моделью по умолчанию измерено на Титане и записано. Целевое число фаза 0
предлагает владельцу после первого замера: опубликованных замеров для GPU класса Mali-G615 нет (`researches/03` §B).

2.7 **Сравнение «до/после».** На экране результата ползунок «до/после» можно схватить пальцем в любом месте картинки, как в
десктопном Upscayl; работают масштабирование двумя пальцами и перемещение.

2.8 **Сохранение.** Результат сохраняется в галерею (`Pictures/KARTUN`) новым файлом, оригинал остаётся нетронутым.
Форматы PNG, JPEG и WebP; у JPEG и WebP есть настройка качества.

2.9 **Поделиться.** Результат отправляется в другое приложение стандартным меню Android «Поделиться».

2.10 **Ссылка из буфера.** Изображение скачивается по ссылке, вставленной из буфера обмена (по нажатию кнопки).

2.11 **Входные форматы.** `[AI]` Открываются минимум 15 входных форматов (слово владельца: «Входных прям очень много нужно»; список фиксирует фаза 4).

2.12 **Языки.** Интерфейс переведён на 10 языков, `[AI]` язык меняется в два касания и по умолчанию берётся из системы.

2.13 **Ошибки.** При сбое загрузки модели, нехватке памяти или отказе GPU приложение не падает и показывает понятное
сообщение. Проверка: три принудительных сбоя на Титане, три понятных сообщения на снимках экрана.

2.14 **Документы.** В репозитории есть инструкция по сборке, лицензии приложения, движка и моделей, список известных
ограничений в README.

## 3. Фазы и ворота

## 4. Технические решения

4.1 **Движок.** Своя обёртка на C++ с JNI над готовой сборкой NCNN `20260526` (`ncnn-20260526-android-vulkan`). Логика
тайлов повторяет MIT-проект Real-ESRGAN-ncnn-vulkan, запасной путь на CPU — MIT-проект realsr-ncnn-vulkan. Код Upscayl
(AGPL-3.0) не используется. Источник: `researches/03` §A.

4.2 **Модели.** `[AI]` по таблице `GOAL.md` §4: `realesrgan-x4plus` (33,4 МБ) — в MVP, `realesrgan-x4plus-anime`
(8,9 МБ) — следом. Замер на Титане (фото 960×1280 пикселей): x4plus — 105 с, быстрая модель из семейства Real-ESRGAN `realesr-general-x4v3`
(2,4 МБ) — 6,6 с; модель по умолчанию — вопрос Q2 `interviews/interview_001_mvp_forks.md`. Все три под
BSD-3; файлы берутся из первоисточника (релиз xinntao), рядом кладётся текст лицензии.

4.3 **Платформа.** minSdk 36 и targetSdk 36 (Android 16, слово владельца в `GOAL.md`), только `arm64-v8a`, страницы
памяти 16 КБ (требование Google Play). Kotlin, Jetpack Compose, MVVM, корутины.

4.4 **Фоновая работа.** Обработка идёт в службе переднего плана типа `mediaProcessing` с уведомлением о прогрессе
(Android 15+; лимит 6 ч в сутки).

4.5 **Память.** Итог 4× от фото 12 Мп — это 192 Мп (768 МБ в памяти). Результат собирается тайлами в нативной памяти и
пишется на диск по частям; целиком в Java-памяти он не держится. Формат WebP ограничен стороной 16 383 пикселей, для
больших результатов приложение предлагает PNG или JPEG.

4.5.1 **Масштаб 1×–16×.** Слово владельца «выбор масштаба ползунком делаем, от x1 до x16» (interview #002). `[AI]` До 4× —
один проход модели 4× и уменьшение до выбранного размера; выше 4× — два прохода (4× · 4×) и уменьшение. Фото 12 Мп при 16×
даёт 3 072 Мп, поэтому лимит итоговых мегапикселей фазы 1 обязателен: выше лимита приложение предлагает меньший масштаб.

4.6 **Стиль.** Стиль Криника из `researches/01`: фон `#0D0D0D`, карточки `#1A1A1A`, акцент `#FF1A8C`, только тёмная тема;
главный путь — вариант A макетов с правками владельца (interview #002, Q1); шрифт — вопрос Q2 того же интервью.
Макеты: `design/kartun-mockups.html`, лист KUIPS `design/flow-map.html`.

4.7 **Языки.** `[AI]` по списку, который владелец выбрал для KrinikCam (`researches/01` §4): RU, EN, ES, PT, ZH, HI, BN,
FR, DE, AR; английский — язык по умолчанию, русский — первый по качеству, арабский проверяет зеркальную раскладку.

4.8 **Выходные форматы.** `[AI]` по заказу владельца («обязательно webP, Png, Jpeg с настройкой качества»): PNG, JPEG и
WebP в фазе 3; четвёртый и пятый (кандидаты HEIC и AVIF) — в фазе 4 после пробы кодеков на Титане.

4.9 **Сеть.** Разрешение `INTERNET` для скачивания по ссылке — вопрос Q1 `interviews/interview_001_mvp_forks.md`.

## 5. Риски

5.1 **Высокие (защита строится сразу):**
1) Движок не заработает на Android → фаза 0 проверяет его до любого интерфейса.
2) Сбой GPU «device lost» на больших тайлах (самая частая поломка аналогов) → размер тайла от бюджета памяти GPU, повтор с
   тайлом вдвое меньше, затем CPU.
3) Чёрная картинка при половинной точности (fp16) на части GPU Mali и Adreno → безопасный режим fp32 и сверка с эталоном.
4) Нехватка памяти на больших фото → тайлы, запись по частям, лимит итоговых мегапикселей.
5) Случайное заимствование кода под AGPL → правило в `AGENT_GUIDE.md` → Code style, источники движка только MIT/BSD.

5.2 **Средние (защита строится, когда риск проявится):** лимит фоновой службы 6 ч в сутки; нагрев и троттлинг планшета на длинных прогонах;
скачивание по ссылке требует разрешения сети (вопрос Q1 `interviews/interview_001_mvp_forks.md`).

5.3 **Низкие (помним):** проверка разработчика Android для установки APK с 2027 года; перепродажа клонов под MIT
(защищает товарный знак).
