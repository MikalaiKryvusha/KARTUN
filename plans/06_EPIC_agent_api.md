## 1. Цель

**Боль.** Планшет или телефон с KARTUN простаивает. ИИ-агент на компьютере (Claude Code, Codex и другие) не может отдать
устройству фото на апскейл без человека у экрана.

**Цель (Achieve).** Агент на компьютере отправляет изображение на устройство с KARTUN и получает увеличенный результат с
отчётом о прогоне. Путь первый — кабель или отладка по Wi-Fi через ADB. Путь второй — локальная сеть: агенту хватает IP
устройства и порта приложения. Экран устройства при этом никто не трогает.

**Чего избегаем (Avoid).** Изображение уходит дальше устройства, которому его прислали. Посторонний запускает задания
без ведома владельца устройства. Агентское задание перехватывает экран владельца (урок EXP-0010).

## 2. Критерии приёмки

Проверку проводит агент на Титане (`HOUSE_RULES.md` §3) и пишет отчёт прогона в `testcases/reports/`. Числа и имена,
выбранные агентом, помечены `[AI]`. Команды ниже — с компьютера, из корня репозитория.

### Фаза A — кабель (ADB), CLI на компьютере, документ API

A1 **Сведения об устройстве.** `node tools/kartun-cli.mjs info` печатает одну строку JSON с `"ok":true`, версией KARTUN,
моделью устройства, строкой видеочипа и списком моделей с полем `id`; код выхода 0. Проверка: прогон на Титане, вывод в
отчёте.

A2 **Апскейл.** `node tools/kartun-cli.mjs upscale engine/third_party/testdata/test256.png --model realesrgan-x4plus --scale 4`
кладёт файл `test256_x4.png` размером 1024×1024 рядом с входным и печатает одну строку JSON с `"state":"succeeded"`,
моделью, `gpu`, временем в мс и размером результата. Проверка: PSNR результата к эталону движка на ПК
`engine/third_party/testdata/ref_x4plus_256.png` не ниже 38 дБ (допуск критерия 2.4 MVP).

A3 **Масштабы и форматы.** Масштабы 1×, 2×, 4×, 8× и форматы PNG, JPEG, WebP дают файлы нужного размера и формата.
Проверка: шесть прогонов на картинке 256×256, размеры и подписи файлов в отчёте.

A4 **Без экрана.** Задание проходит, когда KARTUN закрыт (`am force-stop`) и экран Титана выключен. Экран владельца не
меняется: верхнее окно до и после задания одно и то же. Проверка: `adb shell dumpsys activity activities` (строка
`topResumedActivity`) до и после прогона.

A5 **Отмена.** `node tools/kartun-cli.mjs cancel <job>` во время прогона переводит задание в `"state":"canceled"` не позже
5 с `[AI]`. Проверка: прогон модели `realesrgan-x4plus` на `engine/third_party/testdata/test1mp.png` (≈ 89 с на Титане по
замеру фазы 0), отмена на 30-й секунде, время от команды до статуса в отчёте.

A6 **Понятные ошибки.** Несуществующая модель даёт `"code":"model_not_installed"` и код выхода 1; отключённое устройство
даёт `"code":"no_device"` и код выхода 3. Проверка: оба случая в отчёте.

A7 **Только ADB.** Другое приложение на устройстве не может отдать задание: запуск службы агента не из adb отклоняется.
Проверка: команда от имени приложения (`run-as com.kriniks.kartun.debug am start-foreground-service …`) получает отказ
в разрешении.

A8 **Документ для агентов.** `docs/agent-api.md` описывает команды, поля JSON, состояния задания и коды ошибок. Проверка:
свежий субагент получает только этот документ и проходит A1 и A2 без подсказок человека.

A9 **Чистота устройства.** После `upscale` в папке `files/agent/` на устройстве не остаётся файлов задания (правило R1).
Проверка: `adb shell ls` папки после прогона.

A10 **Офлайн.** A2 проходит в режиме полёта (критерий 2.5 MVP).

### Фаза B — локальная сеть

B1 `[OWNER]` **IP и порт — и этого хватает.** Слова владельца, чат 2026-10-15 ≈ 23:58 +03:00: «можно чтобы просто в
локальной сети умело работать» · «не обязательно по интернету» · «чтобы IP девайса и порт приложения можно было дать, и
этого хватало для работы по локальной сети». Проверка: на компьютере без какой-либо настройки
`curl http://<ip>:<порт>/` отвечает описанием API (список адресов API и пример команды), а
`curl --data-binary @engine/third_party/testdata/test256.png "http://<ip>:<порт>/v1/upscale?scale=4&wait=1" -o out.png`
даёт `out.png` 1024×1024. Вид адреса (`http` или `https`) и ключ доступа зависят от ответов на развилки §6.1 и §6.2.

B2 **Включается только рукой владельца устройства.** После установки сервер выключен: запрос на порт получает отказ
соединения. Включает его переключатель «Станция для ИИ-агентов» в «Настройках»; рядом показаны адрес и порт. Пока сервер
включён, в шторке висит уведомление; выключение переключателя закрывает порт. Проверка: три снимка экрана и три запроса
`curl` (до включения, включён, после выключения).

B3 **Только локальная сеть.** Сервер отвечает адресам локальной сети. Проверка: запрос с адреса вне частных диапазонов
получает отказ (граница «локальной сети» — развилка §6.5).

B4 **CLI по сети.** `node tools/kartun-cli.mjs upscale test256.png --host <ip>:<порт>` даёт тот же результат, что A2.

B5 **Чужие результаты закрыты.** Номер задания — случайное 128-битное число; списка заданий в API нет. Проверка: запрос
`/v1/jobs/<случайный номер>` получает `404`.

B6 **Фон.** Задание по сети проходит при выключенном экране Титана на зарядке. Проверка: прогон B1 с выключенным экраном.

B7 **Android 17.** С флагом `RESTRICT_LOCAL_NETWORK` (так Титан на Android 16 ведёт себя как Android 17) включение
переключателя спрашивает разрешение на локальную сеть; после согласия B1 проходит. Проверка: снимок окна разрешения и
прогон B1.

## 4. Технические решения

Подробности и источники — `researches/10_agent_api_recon.md`.

4.1 **Один слой заданий, две двери.** Движок, план проходов (8× и 16× — два прохода 4×), лестница запасных путей
(тайл 200 → 100 → процессор) и лимиты сейчас живут в `UpscaleViewModel`. Они переезжают в один общий объект движка с
одним потоком. Интерфейс, дверь ADB и дверь сети ставят задания в него. Один поток нужен, так как объекты ncnn и Vulkan
падают на Mali при работе из двух потоков (`researches/03` §B, урок 7). Задания идут по очереди; сверх `[AI]` 8 в
очереди приходит ответ `busy`.

4.2 **Дверь ADB.** Компьютер запускает службу агента командой `adb shell am start-foreground-service`. Служба отдана
наружу только тем, у кого есть разрешение `android.permission.DUMP`; оно есть у adb и закрыто для обычных приложений.
Так же защищены служебные приёмники библиотек Google WorkManager и ProfileInstaller. Исходный код Android разрешает
оболочке adb запускать службу переднего плана, когда приложение в фоне или закрыто (`researches/10` §1.4). Служба
работает с типом `mediaProcessing`, как и `UpscaleService`.

4.3 **Файлы.** Вход кладётся `adb push` в `/sdcard/Android/data/<пакет>/files/agent/`; там же служба пишет файл
состояния задания (JSON) и результат; CLI забирает результат `adb pull` и удаляет файлы задания. Другие приложения эту
папку не видят.

4.4 **Один формат задания.** Состояния: `queued`, `running`, `succeeded`, `failed`, `canceled`. Файл состояния по ADB и
ответ сервера по сети — один и тот же JSON; документ API описывает одну схему и два способа доставки.

4.5 **CLI.** `tools/kartun-cli.mjs` на Node без сторонних пакетов: `info`, `models`, `upscale`, `status`, `cancel`. Одна
строка JSON на результат в стандартный вывод, прогресс — в поток ошибок; коды выхода 0 — готово, 1 — задание не прошло,
2 — неверная команда, 3 — нет устройства. adb вызывается через `spawnSync` (урок EXP-0002).

4.6 **Дверь сети.** Сервер Ktor (лицензия Apache-2.0) внутри службы переднего плана типа `connectedDevice`. Включается
только переключателем; при перезапуске устройства сам не стартует. Корень `GET /` описывает API, чтобы агенту хватало
адреса. Порт по умолчанию `[AI]` 8765, меняется в настройках. Сеть по-прежнему не участвует в самом апскейле: правило
interview #001, Q1 = A дополняется второй ручной кнопкой — переключателем станции (слова владельца 2026-10-14 ≈ 14:15,
≈ 22:41 и 2026-10-15).

4.7 **Android 17.** У KARTUN `targetSdk = 37`: на Android 17 приём входящих соединений требует разрешения
`ACCESS_LOCAL_NETWORK`, его приложение спрашивает при включении переключателя.

## 5. Риски

5.1 **Высокие (защита строится сразу):**
1) Задание агента и задание из интерфейса одновременно грузят разные модели в один видеочип → один поток движка и
   очередь (§4.1).
2) Переезд движка из `UpscaleViewModel` ломает обычный путь «выбрал фото → улучшил» → после переезда — прогон
   интерфейса на Титане и зелёные JVM-тесты до любой работы над агентом.
3) Правки каталога моделей идут в тех же файлах прямо сейчас → фаза A начинает код после коммита работы по `plans/05`.
4) Без ключа любой в той же Wi-Fi пользуется станцией и видит снимки в эфире открытой сети → цена названа владельцу в
   §6.1–6.2; сервер выключен по умолчанию; результаты удаляются после выдачи.

5.2 **Средние (защита строится, когда риск проявится):**
1) Лимит Android для `mediaProcessing` — 6 часов из каждых 24 на всё приложение → задание после лимита завершается
   кодом `quota`, документ API говорит об этом.
2) Два больших фото в памяти сразу (интерфейс и агент) → общие лимиты 100 Мп на входе и 500 Мп на выходе; при нехватке
   памяти — ответ `too_big`.
3) Doze отключает сеть у устройства без зарядки с выключенным экраном → в настройках подпись «держите устройство на
   зарядке», `info` сообщает `charging`.
4) Нагрев планшета на долгой серии заданий.

5.3 **Низкие (помним):** адрес устройства меняется при выдаче нового адреса роутером → адрес и порт показаны на экране
настройки; мобильные сети за NAT оператора — вне задачи (сеть только локальная).

## 6. Развилки владельца

Рекомендация агента отмечена ✅. Источники — `researches/10` §2.

6.1 **HTTP или HTTPS в локальной сети.**
- ✅ HTTP: агенту хватает адреса и порта — ровно слова владельца; так работают Ollama, ComfyUI, AUTOMATIC1111. Цена:
  снимки идут по Wi-Fi без шифрования; в открытой сети их видит любой рядом, в домашней — тот, кто знает пароль Wi-Fi.
- HTTPS с самоподписанным сертификатом: снимки зашифрованы; агенту нужен флаг `curl -k` или отпечаток сертификата —
  это настройка на компьютере. Так работает LocalSend.

6.2 **Ключ доступа.**
- ✅ Без ключа по умолчанию, с переключателем «Требовать ключ» в настройках. Цена: пока ключ выключен, любой в той же
  Wi-Fi отдаёт станции задания, грузит видеочип и тратит батарею; чужие результаты он не получает (§2 B5).
- Ключ всегда: агенту нужен заголовок `Authorization: Bearer <ключ>`, ключ переписывается с экрана устройства.

6.3 **Дверь ADB в сборке «KARTUN».**
- ✅ Есть в обеих сборках, без переключателя: пользоваться ею может только тот, кто сам включил отладку по USB или по
  Wi-Fi и подключил компьютер.
- Только в «Debug KARTUN».

6.4 **Переключатель станции после перезапуска приложения.**
- ✅ Сервер выключается вместе с приложением и после перезагрузки устройства; включение — снова рукой.
- Переключатель помнит состояние и поднимает сервер при каждом запуске KARTUN.

6.5 **Что считать локальной сетью.**
- ✅ Только частные адреса Wi-Fi (`192.168.x.x`, `10.x.x.x`, `172.16–31.x.x`) и адреса внутри устройства.
- Плюс адреса VPN-сетей вроде Tailscale (`100.64.0.0/10`): станция доступна с компьютера вне дома, через сеть Tailscale.

6.6 **MCP-сервер для Claude Code.**

- В этом эпике сразу после фазы A.
