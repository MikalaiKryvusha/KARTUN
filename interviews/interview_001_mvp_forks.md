(`ideas/02`). Режиму ADB сеть не нужна. Серверу HTTPS в локальной сети разрешение `INTERNET` нужно в любом случае:
вариант C ниже его исключает, вариант B оставляет его только полной сборке.

### Q1. Как приложению получать изображение по ссылке и что писать про офлайн?

**Answer target:** `plans/01_EPIC_mvp.md` §2.10 и §4 (решение о сети); `MASTER_PLAN.md` §3, фаза 4; будущий README (строка о сети)

**Origin:** вопрос задал агент 2026-10-14 при планировании MVP. Он решает, будет ли у KARTUN разрешение на сеть, и
блокирует критерий приёмки 2.10 «Ссылка из буфера» и текст описания приложения. Фаза 0 (проверка движка) от ответа не зависит.

- **A) (recommended) Одна сборка с разрешением сети; сеть работает только по кнопке «Вставить ссылку»**
  - Situation. Пользователь скопировал в браузере ссылку на картинку `https://…/photo.jpg`.
  - Action. Пользователь нажимает в KARTUN кнопку «Вставить ссылку».
  - Result. Картинка скачивается и открывается в превью; апскейл дальше идёт без сети, как и для фото из галереи. В
    описании приложения стоит «Обработка офлайн. Сеть — только для скачивания по вашей ссылке».
  - Check. В манифесте одно разрешение `INTERNET`; прогон апскейла в режиме полёта на Титане даёт результат.
- **B) Две сборки: «Offline» без разрешения сети и полная со ссылкой**
  - Situation. Пользователь открывает страницу релиза на GitHub.
  - Action. Пользователь выбирает один из двух APK: `KARTUN-offline` или `KARTUN`.
  - Result. В сборке `KARTUN-offline` кнопки «Вставить ссылку» нет, и в карточке приложения нет разрешения на сеть.
    В сборке `KARTUN` кнопка есть. Агент собирает, тестирует и выпускает обе.
  - Check. Манифест сборки `offline` без `INTERNET`, манифест полной — с ним; обе проходят прогон на Титане.
- **C) Без сети в MVP: картинка из браузера приходит через «Поделиться → KARTUN»**
  - Situation. Пользователь видит картинку в браузере.
  - Action. Пользователь долго нажимает на картинку, выбирает «Поделиться» и затем KARTUN.
  - Result. Браузер сам скачивает картинку и передаёт её в KARTUN; у приложения нет разрешения на сеть. Кнопки
    «Вставить ссылку» в MVP нет, она переносится в фазу 5.
  - Check. В манифесте нет `INTERNET`; приём картинки через «Поделиться» проходит на Титане.

### Q2. Какая модель работает по умолчанию, когда пользователь просто нажимает «Улучшить»?

**Answer target:** `plans/01_EPIC_mvp.md` §4.2 (модели) и §2.6 (критерий скорости); `MASTER_PLAN.md` журнал решений

**Origin:** вопрос задал агент 2026-10-14 14:17 после замера на Титане (фаза 0, `testcases/reports/2026-10-14_F0_engine_probe.md`).
В `GOAL.md` §4 записано: «Для первой версии достаточно одной проверенной модели» и строка таблицы «Real-ESRGAN <!-- ref-ok: the GOAL.md text is quoted in full right here, the address only names its source -->
x4plus | Универсальный апскейл фотографий | P0». Замер на Титане показал: x4plus обрабатывает фото 1,2 Мп за 105 с,
быстрая модель того же семейства — за 6,6 с, разница в 16 раз. Ответ решает, что
пользователь получает по одной кнопке, и задаёт число в критерии скорости 2.6. Картинка сравнения на твоём фото (улей,
фрагмент 700×700 из результата 3840×5120): `engine/third_party/testdata/compare_models_photo1.png` — агент открывает её
тебе на экране; файл лежит вне git, так как фото твоё.

- **A) (recommended) По умолчанию быстрая модель, качественная x4plus — второй карточкой «Максимальное качество»**
  - Situation. Пользователь выбрал фото 960×1280 на Титане.
  - Action. Пользователь нажимает «Улучшить» без выбора модели.
  - Result. Через 7 секунд готово фото 3840×5120: чёткие края, гладкие поверхности. Карточка «Максимальное
    качество» даёт естественную фактуру за 105 секунд.
  - Check. Замер на Титане: быстрая модель 6 569 мс, x4plus 104 805 мс (отчёт прогона фазы 0).
- **B) По умолчанию качественная x4plus, быстрая — второй карточкой**
  - Situation. Пользователь выбрал то же фото.
  - Action. Пользователь нажимает «Улучшить».
  - Result. Около 1 минуты 45 секунд пользователь видит прогресс, затем получает фото с естественной фактурой. Быстрая
    модель доступна карточкой «Быстро».
  - Check. Замер на Титане: x4plus 104 805 мс на фото 1,2 Мп.
- **C) Одна модель x4plus в MVP, как в таблице `GOAL.md`**
  - Situation. Пользователь выбрал то же фото.
  - Action. Пользователь нажимает «Улучшить».
  - Result. Выбора модели в MVP нет, обработка идёт около 1 минуты 45 секунд. Быстрая модель появляется после MVP.
  - Check. В APK одна модель, 33,4 МБ.
