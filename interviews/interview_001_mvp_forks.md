## Context / what I already found in the code

В коде приложения есть только проба движка фазы 0, скачивания по ссылке в нём нет. В `GOAL.md` стоят рядом две
записи владельца: подзаголовок «Open-source · Offline · AI-powered» и пункт личного заказа «Возможность скачать
изображение по ссылке вставив на нее ссылку прямо из буфера обмена в приложение». Для скачивания по ссылке Android
требует разрешения `INTERNET`. Это разрешение видно в карточке приложения и в разделе «Безопасность данных» Google Play.
Апскейл в любом варианте идёт на устройстве без сети (`researches/03` §D).

Дополнение 2026-10-14 ≈ 14:17: владелец заказал API для ИИ-агентов (`ideas/02`): «в KARTUN должен быть понятный API,
CLI, чтобы ИИ агенты могли им пользоваться по проводу через ADB, или еще-как-то, или в локальной вай-фай сети по HTTPS».
Режиму ADB сеть не нужна. Серверу HTTPS в локальной сети нужно разрешение `INTERNET`: в варианте A ниже сервер возможен,
в варианте B — только в сборке `KARTUN`, в варианте C сервер отложен вместе с разрешением. Сервер в плане стоит после MVP.

Дополнение 2026-10-14 ≈ 14:45: владелец решил давать в каталоге много моделей со скачиванием на устройство (интервью
№002, ответ на Q1): «моделей в настройках нужно будет давать на выбор много… нужно будет ждать их скачивания на
устройство для того, чтобы с этой моделью работать». Скачивание моделей тоже требует разрешения `INTERNET`; в варианте C каталог моделей ждёт сети до фазы 5.

Языки и выходные форматы агент выбрал сам по источникам, это решение легко пересмотреть: языки — по списку KrinikCam,
форматы — PNG, JPEG и WebP плюс два после пробы кодеков на Титане (`plans/01_EPIC_mvp.md` §4.7, §4.8). Модель по
умолчанию — вопрос Q2 ниже.

## QUESTIONS

### Q1. Как приложению получать изображение по ссылке и что писать про офлайн?

**Answer target:** `plans/01_EPIC_mvp.md` §2.10 и §4.9 (решение о сети); `MASTER_PLAN.md` §3, фаза 4; будущий README (строка о сети)

**Origin:** вопрос задал агент 2026-10-14 при планировании MVP. Ответ решает, будет ли у KARTUN разрешение на сеть; от
ответа зависят критерий приёмки 2.10 «Ссылка из буфера» и текст описания приложения. Фаза 0 (проверка движка) от ответа
не зависит.

<!-- archaeology: search "скача|изображен|ссылк" → 52 hits · read: GOAL.md, MASTER_PLAN.md, plans/01_EPIC_mvp.md · prior: "Возможность скачать изображение по ссылке вставив на нее ссылку прямо из буфера обмена в приложение" + "Open-source · Offline · AI-powered" — GOAL.md (личный заказ владельца и подзаголовок); оба слова в силе, вопрос о том, как их совместить -->

- **A) (recommended) Одна сборка с разрешением сети; сеть работает только по кнопке «Вставить ссылку»**
  - Situation. Пользователь скопировал в браузере ссылку на картинку `https://…/photo.jpg`.
  - Action. Пользователь нажимает в KARTUN кнопку «Вставить ссылку».
  - Result. Картинка скачивается и открывается в превью; апскейл дальше идёт без сети, как и для фото из галереи. В
    описании приложения стоит «Обработка офлайн. Сеть — только для скачивания по вашей ссылке».
  - Check. Из сетевых разрешений в манифесте только `INTERNET`; прогон апскейла в режиме полёта на Титане даёт результат.
- **B) Две сборки: «Offline» без разрешения сети и полная со ссылкой**
  - Situation. Пользователь открывает страницу релиза на GitHub.
  - Action. Пользователь выбирает один из двух APK: `KARTUN-offline` или `KARTUN`.
  - Result. В сборке `KARTUN-offline` кнопки «Вставить ссылку» нет, и в карточке приложения нет разрешения на сеть.
    В сборке `KARTUN` кнопка есть. Агент собирает, тестирует и выпускает обе.
  - Check. Манифест сборки `offline` без `INTERNET`, манифест полной — с ним; обе проходят прогон на Титане.
- **C) Без сети в MVP: картинка из браузера приходит через «Поделиться → KARTUN»**
  - Situation. Пользователь видит картинку в браузере.
  - Action. Пользователь нажимает на картинку и держит палец, выбирает «Поделиться» и затем KARTUN.
  - Result. Браузер сам скачивает картинку и передаёт её в KARTUN; у приложения нет разрешения на сеть. Кнопки
    «Вставить ссылку» в MVP нет, она переносится в фазу 5.
  - Check. В манифесте нет `INTERNET`; приём картинки через «Поделиться» проходит на Титане.

### Q2. Какая модель работает по умолчанию, когда пользователь просто нажимает «Улучшить»?

**Answer target:** `plans/01_EPIC_mvp.md` §4.2 (модели) и §2.6 (критерий скорости); журнал решений `MASTER_PLAN.md`

**Origin:** вопрос задал агент 2026-10-14 после замера на Титане (прогоны 10 и 11 отчёта
`testcases/reports/2026-10-14_F0_engine_probe.md`). В `GOAL.md` §4 записано: «Для первой версии достаточно одной <!-- ref-ok: the GOAL.md text is quoted in full right here, the address only names its source -->
проверенной модели» и строка таблицы «Real-ESRGAN x4plus | Универсальный апскейл фотографий | P0». Замер на фото
владельца 960×1280 пикселей (GPU, тайл 200): `realesrgan-x4plus` — 105 с, быстрая модель `realesr-general-x4v3` из
семейства Real-ESRGAN — 6,6 с, разница в 16 раз. Быстрая модель в замере — её ncnn-файл из установленного Upscayl
(`upscayl-lite-4x`, конвертация тех же весов BSD-3); свою конвертацию из оригинальных весов агент сделает и
перемерит при закрытии фазы 0. Ответ решает, что пользователь получает по одной кнопке, и задаёт число в критерии
скорости 2.6. Картинка сравнения на фото владельца (улей, фрагмент 700×700 пикселей из результата 3840×5120
пикселей): `engine/third_party/testdata/compare_models_photo1.png`. Агент запустил её открытие на экране владельца;
появилось ли окно, агент не проверял. Файл лежит вне git, так как фото личное.

<!-- archaeology: search "модел|умолчан|быстр|качественн" → 53 hits · read: GOAL.md, plans/01_EPIC_mvp.md, researches/03 · prior: "Real-ESRGAN x4plus | Универсальный апскейл фотографий | P0" + "Для первой версии достаточно одной проверенной модели" — GOAL.md §4 (таблица из консультации ЧатГПТ в GOAL.md; скорость на телефоне тогда не была известна) -->

- **A) (recommended) По умолчанию быстрая модель, качественная x4plus — второй карточкой «Максимальное качество»**
  - Situation. Пользователь выбрал фото 960×1280 пикселей на Титане.
  - Action. Пользователь нажимает «Улучшить» без выбора модели.
  - Result. Через 7 с готово фото 3840×5120 пикселей: края чёткие, мелкая фактура сглажена (оценка агента по картинке
    сравнения). Карточка «Максимальное качество» даёт естественную фактуру за 105 с.
  - Check. Отчёт прогона, прогоны 10 и 11: быстрая модель 6 569 мс, x4plus 104 805 мс.
- **B) По умолчанию качественная x4plus, быстрая — второй карточкой**
  - Situation. Пользователь выбрал фото 960×1280 пикселей на Титане.
  - Action. Пользователь нажимает «Улучшить».
  - Result. Около 105 с пользователь видит прогресс, затем получает фото с естественной фактурой. Быстрая модель
    выбирается карточкой «Быстро».
  - Check. Отчёт прогона, прогон 11: x4plus 104 805 мс на фото 1,2 Мп.
- **C) Одна модель x4plus в MVP, как в таблице `GOAL.md`**
  - Situation. Пользователь выбрал фото 960×1280 пикселей на Титане.
  - Action. Пользователь нажимает «Улучшить».
  - Result. Выбора модели в MVP нет, обработка идёт около 105 с. Быстрая модель появляется после MVP.
  - Check. В APK одна модель, 33,4 МБ.
- **D) your own answer** —
