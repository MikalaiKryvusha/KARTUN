## Context / what I already found in the code

Фаза 0 закрыта замером. Модель по умолчанию — быстрая `realesr-general-x4v3` (ваш ответ в интервью №001, Q2 = A). KARTUN
теперь конвертирует её сам из оригинальных весов. На Титане через наш движок она совпадает с оригинальной нейросетью:
52,3 дБ, у бикубика 31,4 дБ.

| Картинка | GPU (Vulkan) | CPU (запасной путь) |
|---|---|---|
| тест 256×256 | 0,4 с | 4,8 с |
| тест 1024×1024 (1 Мп) | **5,8 с** | 84,8 с |

для GPU класса Mali-G615 нет (`researches/03` §B), сравнить не с чем — число задаёте вы.

**Answer target:** `plans/01_EPIC_mvp.md` §2.6 (критерий «Скорость»); ворота фазы 1 в `plans/01_EPIC_mvp.md` §3

- **A) (recommended) Не дольше 10 секунд на фото 1 Мп на Титане**
  - Situation. Пользователь выбрал фото 1 Мп и модель по умолчанию, масштаб 4×.
  - Action. Пользователь нажимает «Улучшить».
  - Result. Результат на экране не позже чем через 10 с; сейчас выходит 5,8 с, запас на нагрев планшета и работу экранов — 4 с.
  - Check. `node tools/titan-probe.mjs --in test1mp.png --model realesr-general-x4v3 --gpu true` печатает `upscale_ms` не больше 10000.
- **B) Не дольше 7 секунд**
  - Situation. То же фото 1 Мп, модель по умолчанию, масштаб 4×.
  - Action. Пользователь нажимает «Улучшить».
  - Result. Результат не позже чем через 7 с; запас над сегодняшним замером — чуть больше секунды, нагретый планшет может
    не уложиться, и агент будет искать ускорение.
  - Check. Та же команда печатает `upscale_ms` не больше 7000.
- **C) Нормы нет — только записывать время**
  - Situation. То же фото 1 Мп.
  - Action. Пользователь нажимает «Улучшить».
  - Result. Время показывается и записывается в отчёт каждого прогона, но замедление не останавливает выпуск.
  - Check. В каждом отчёте прогона `testcases/reports/` есть строка с `upscale_ms` для 1 Мп.
- **D) your own answer** —
