## 1. Видение одной строкой

**KARTUN** — Android-приложение, которое увеличивает разрешение фотографии нейросетью Real-ESRGAN прямо на телефоне:
пользователь выбирает фото, нажимает одну кнопку, сравнивает «до» и «после» ползунком под пальцем, сохраняет результат в
галерею или делится им. Обработка идёт на устройстве, на движке NCNN с ускорением Vulkan. Интерфейс сделан в розовом стиле
Криника и переведён на 10 языков, код открыт под MIT.

## 2. Принципы

2.1 **Сначала движок, потом экраны.** Главный риск проекта — сборка и стабильная работа нейросети на Android (`GOAL.md`,
«Три решения», пункт 2). Первая веха — апскейл тестового изображения на планшете Titan 1. Интерфейс начинается после неё.

2.2 **Честный результат.** Апскейл делает только нейросеть. Если движок не запустился, пользователь видит понятную ошибку.
Поддержка Vulkan заявляется после проверки на устройстве. Успешная компиляция доказательством работы движка не считается
(`GOAL.md` §12).

2.3 **Готово — это прогон на Титане.** Функция считается работающей, когда агент прошёл её на планшете пользовательским
путём и прочитал результат: картинку, лог, размер файла (`HOUSE_RULES.md` §3, правило R1).

2.4 **Чистые лицензии.** Код KARTUN — MIT. Движок пишется своей обёрткой по образцу MIT-проектов поверх NCNN (BSD-3); код
Upscayl под AGPL-3.0 не копируется. В приложение идут только модели, разрешённые для коммерческого использования
(`researches/03` §A, §C).

2.5 **Стиль Криника.** Почти чёрный фон, один розовый акцент `#FF1A8C`, плоские тёмные карточки, кнопка `[i]` у каждой
настройки (`researches/01`).

2.6 **Простота Upscayl.** Один основной экран и минимум настроек. Технические параметры модели пользователю не показываются.

## 3. Фазы

Фазы 0–4 составляют MVP. Подробный план MVP с критериями приёмки — `plans/01_EPIC_mvp.md`, развилки владельца —
`interviews/interview_001_mvp_forks.md`.

### Фаза 0 — Фундамент и проверка движка на Титане
- **Цель фазы:** тестовое изображение увеличивается в 4 раза моделью Real-ESRGAN на Титане через Vulkan и через CPU;
  время каждого прогона записано.
- **Шаги:** Gradle-проект под Android 16; модуль движка на C++ с JNI поверх готовой сборки NCNN `20260526`; две модели
  (быстрая и качественная); консольная проба на Титане; эталонная картинка для автоматической сверки.
- **Статус:** 🔲 следующая

### Фаза 1 — Надёжный движок
- **Цель фазы:** движок выдерживает серию изображений разного размера без падений и утечек памяти.
- **Шаги:** обработка тайлами; прогресс по тайлам; отмена между тайлами; запасной путь при сбое GPU (меньший тайл, затем
  fp32, затем CPU); запись результата на диск по частям для больших изображений; лимит итоговых мегапикселей.
- **Статус:** 🔲

### Фаза 2 — Основной сценарий
- **Цель фазы:** пользователь проходит весь путь без инструментов разработчика: выбрал фото → увидел превью и разрешение →
  выбрал модель и масштаб → нажал «Улучшить» → увидел прогресс → сравнил «до» и «после».
- **Шаги:** системный выбор фото; экран с превью; выбор модели карточками; масштаб 2× и 4×; обработка в фоновой службе с
  уведомлением; экран результата с ползунком «до/после», который палец хватает в любом месте; масштабирование пальцами и
  перемещение по картинке; тема Криника.
- **Статус:** 🔲

### Фаза 3 — Сохранение и обмен
- **Цель фазы:** готовое изображение лежит в галерее (`Pictures/KARTUN`) и уходит в другое приложение через системное меню
  «Поделиться».
- **Шаги:** сохранение через MediaStore без разрешения на память; форматы PNG, JPEG и WebP с настройкой качества; понятное
  имя файла; приём фото из других приложений («Поделиться → KARTUN»).
- **Статус:** 🔲

### Фаза 4 — Заказ владельца: форматы, ссылка, языки
- **Цель фазы:** приложение открывает много входных форматов, скачивает изображение по ссылке из буфера обмена и говорит на
  10 языках. Первый APK выходит на GitHub по слову владельца.
- **Шаги:** входные форматы системы (JPEG, PNG, WebP, GIF, BMP, HEIC, AVIF, DNG и другие) и форматы из открытых библиотек
  (TGA, PSD, PNM, HDR, TIFF); 4–5 выходных форматов; кнопка «Вставить ссылку»; 10 языков с выбором в два касания; экран «О
  приложении» с лицензиями и диагностикой устройства; README на английском и русском.
- **Статус:** 🔲

### Фаза 5 — После MVP: возможности
- Дополнительные модели с атрибуцией (4xHFA2k, 4xNomos8kSC, Real-CUGAN), импорт своих моделей, пакетная обработка,
  история последних обработок, AVIF/JXL на выходе.

### Фаза 6 — После MVP: распространение
- Подпись релизов ключами из `.env` (правило R2), Obtainium и GitHub Releases, затем каталоги приложений; проверка
  разработчика Android (обязательна для установки с 2027 года).
